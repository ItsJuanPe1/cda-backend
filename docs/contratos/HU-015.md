# Contrato API: HU-015 Editar los datos de mi perfil (docente)

**Estado:** aprobado (2026-10-25) · **Fecha:** 2026-10-25
**HU relacionadas:** HU-022 (ver mi perfil), HU-029 (el administrador edita perfiles)

## Alcance
Desde el módulo «Mi perfil», el docente autenticado edita **solo** su foto, su correo personal y su teléfono.
Nombres, apellidos, correo institucional, código, documento, tipo, categoría, programa, estado y evaluación son de solo lectura.

El docente se identifica **siempre por el correo del JWT** (claim `email`), nunca por un parámetro de la petición.
Ningún endpoint de este contrato recibe un id ni un correo: un docente no puede leer ni modificar el perfil de otro.

## Roles
| Endpoint | Roles |
|---|---|
| `GET /api/docentes/me` | Cualquier usuario autenticado con perfil docente activo |
| `PUT /api/docentes/me/contacto` | `DOCENTE`, `ADMIN` (sobre su propio perfil docente, RN-07) |
| `PUT /api/docentes/me/foto` | `DOCENTE`, `ADMIN` |
| `GET /api/docentes/me/foto` | `DOCENTE`, `ADMIN` |
| `DELETE /api/docentes/me/foto` | `DOCENTE`, `ADMIN` |

---

## 1. `GET /api/docentes/me`: ver mi perfil

**Cambio que rompe el contrato actual:** se elimina el parámetro `?correo=`. El frontend debe dejar de enviarlo en la misma HU.

**200 OK**
```json
{
  "id": 12,
  "codigo": "DOC-0012",
  "nombres": "Ana María",
  "apellidos": "Pérez Gómez",
  "tipo_documento": "CC",
  "numero_documento": "1000000012",
  "correo_institucional": "ana.perez@correounivalle.edu.co",
  "correo_personal": "ana.perez@example.com",
  "telefono": "3001234567",
  "tipo_docente": "HORA_CATEDRA",
  "categoria": "AUXILIAR",
  "code_program": "2724",
  "nombre_programa": "Tecnología en Desarrollo de Software",
  "tiene_foto": true,
  "evaluacion_periodo": "2026-1",
  "evaluacion_valor": 4.50,
  "estado": true,
  "created_at": "2026-10-20T14:00:00",
  "updated_at": "2026-10-25T09:30:00"
}
```
`tiene_foto` indica si hay una foto activa. Si es `false`, el frontend muestra la imagen por defecto.
`correo_personal` y `tiene_foto` también aparecen en el listado de docentes del administrador.
El campo heredado `foto_url` se sigue enviando por compatibilidad, pero no se usa: la foto se obtiene con el endpoint 4.
El parámetro `?correo=` ya no se lee; si el frontend aún lo envía, se ignora.

---

## 2. `PUT /api/docentes/me/contacto`: editar correo personal y teléfono

Reemplaza los dos datos de contacto. Un valor `null` o `""` deja el campo vacío (ambos son opcionales).
Cualquier otro campo en el cuerpo se ignora.

**Petición**
```json
{
  "correo_personal": "ana.perez@example.com",
  "telefono": "3001234567"
}
```

**Validaciones**
| Campo | Regla | Mensaje |
|---|---|---|
| `correo_personal` | Opcional. Formato de correo válido. Máximo 100 caracteres. | «El correo personal no tiene un formato válido» |
| `correo_personal` | No puede terminar en `@correounivalle.edu.co`. | «El correo personal no puede ser institucional» |
| `telefono` | Opcional. Solo dígitos, de 7 a 10. Se guarda como texto para conservar los ceros iniciales. | «El teléfono solo admite de 7 a 10 dígitos» |
| (ambos) | Si los valores son iguales a los guardados. | «No hay cambios para guardar» |

El correo personal se guarda en minúsculas y sin espacios al inicio ni al final.

**200 OK**: el perfil completo (mismo cuerpo que el endpoint 1).

---

## 3. `PUT /api/docentes/me/foto`: subir o reemplazar la foto

`Content-Type: multipart/form-data`, con la parte `foto` (archivo).

**Validaciones**
| Regla | Mensaje |
|---|---|
| Formato JPG o PNG, comprobado por el contenido del archivo y no solo por la extensión. | «Formato o tamaño no válido» |
| Tamaño mayor que 0 y hasta 5 MB (5 242 880 bytes). | «Formato o tamaño no válido» |

Cada docente tiene **una sola foto almacenada**. Si ya existía una (activa o desactivada), la nueva **reemplaza** su contenido y queda activa. La primera vez se crea.

**200 OK**: el perfil completo, con `"tiene_foto": true`.

---

## 4. `GET /api/docentes/me/foto`: obtener mi foto

**200 OK**: el contenido binario de la imagen, con `Content-Type: image/jpeg` o `image/png`.
Como la petición lleva el encabezado `Authorization`, el frontend la descarga con `fetch` y la muestra con `URL.createObjectURL`.

**404** si no hay foto activa: «No tiene foto registrada».

---

## 5. `DELETE /api/docentes/me/foto`: eliminar mi foto

**Desactiva** la foto activa (no la borra de la base). Solo el administrador la elimina directamente en la base de datos.
La confirmación previa la pide el frontend.

**204 No Content**: después, `GET /api/docentes/me` devuelve `"tiene_foto": false`.

**404** si no hay foto activa: «No tiene foto registrada».

---

## Errores comunes
Formato del manejador global actual:
- Errores de validación de campos: `{"status": 400, "error": "Validation Error", "errors": {"correoPersonal": "El correo personal no tiene un formato válido"}}`. La clave es el nombre del atributo Java (`correoPersonal`, `telefono`), no el del campo JSON (corregido el 2026-10-27).
- Resto de errores: `{"status": <código>, "error": "...", "message": "..."}`

| Código | Cuándo | Mensaje |
|---|---|---|
| 400 | Validación fallida | El de la tabla correspondiente |
| 401 | Sin JWT o JWT vencido | «Sesión no válida o expirada» |
| 403 | Rol sin permiso | «No tiene permisos para esta acción» |
| 404 | El correo del JWT no tiene un perfil docente activo | «No se encontró su perfil de docente» |
| 500 | Fallo inesperado | El frontend muestra «No se pudo guardar. Intente de nuevo» (o «No se pudo cargar la imagen» si falló la foto) |

## Mensajes que maneja solo el frontend
«Perfil actualizado», «No se pudo guardar. Intente de nuevo», «No se pudo cargar la imagen», «No se pudo cargar su perfil», y las confirmaciones al guardar, al eliminar la foto y al cancelar con cambios.

## Configuración necesaria
- `spring.servlet.multipart.max-file-size=5MB` y `max-request-size=6MB` (el valor por defecto de Spring es 1 MB). Si se supera, la respuesta es 400 «Formato o tamaño no válido».
- `server.tomcat.max-swallow-size=10MB`, para responder 400 en lugar de cortar la conexión con archivos algo mayores. Igual, el frontend debe comprobar el tamaño antes de subir.
- En SIA, confirmar con el coordinador de salas que Apache no limita el cuerpo de la petición por debajo de 6 MB (`LimitRequestBody`).
