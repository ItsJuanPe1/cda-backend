# Contrato API: HU-040 Crear y editar programas académicos

**Estado:** aprobado (2026-10-27) · **Fecha:** 2026-10-27
**HU relacionadas:** HU-041 (desactivar o eliminar), HU-042 y HU-043 (cohortes), HU-017 y HU-032 (mallas), HU-020/036/037 (coordinadores)
**Migración:** V15 (`V15__hu040_programas_codigo_jornada_estado.sql`)

## Alcance
El administrador crea, consulta, edita y desactiva programas académicos. Un programa tiene código de 4 dígitos,
nombre, jornada (diurna, nocturna o ambas), duración en semestres por jornada, ingreso (semestral o anual) y estado.
Editar un programa no toca sus mallas, cohortes ni coordinador (criterio 4). No hay borrado físico (RN-13).

Los endpoints ya existen en `/api/programas`. Este contrato **agrega campos** y cambia el comportamiento del `DELETE`;
ningún campo actual se quita ni cambia de nombre.

## Roles
| Endpoint | Roles |
|---|---|
| `GET /api/programas` | `ADMIN`, `COORDINADOR` |
| `GET /api/programas/{code}` | `ADMIN`, `COORDINADOR` |
| `POST /api/programas` | `ADMIN` |
| `PUT /api/programas/{code}` | `ADMIN` |
| `DELETE /api/programas/{code}` | `ADMIN` |

Son las reglas que ya tiene `SecurityConfig`; no cambian.

## Cambio de datos que el frontend debe conocer
Al aplicar V15, los códigos con sufijo de jornada pasan a 4 dígitos (`2724-DIU` → `2724`). El frontend no debe tener
códigos escritos a mano, y los coordinadores con sesión abierta deben volver a iniciarla (el token lleva el código viejo).

## Representación de un programa

```json
{
  "code_program": "3846",
  "name_program": "Administración de Empresas",
  "jornada": "AMBAS",
  "numero_semestre": 10,
  "semestres_nocturna": 11,
  "ingreso": "SEMESTRAL",
  "estado": "ACTIVO",
  "id_facultad_programa": 4,
  "total_asignaturas": 54
}
```

| Campo | Tipo | Notas |
|---|---|---|
| `code_program` | texto | 4 dígitos. No se edita. |
| `name_program` | texto | Máximo 100 caracteres. |
| `jornada` | `DIURNA` \| `NOCTURNA` \| `AMBAS` | |
| `numero_semestre` | entero o `null` | Duración en jornada diurna. `null` si la jornada es `NOCTURNA`. |
| `semestres_nocturna` | entero o `null` | Duración en jornada nocturna. `null` si la jornada es `DIURNA`. |
| `ingreso` | `SEMESTRAL` \| `ANUAL` | Descriptivo; no interviene en la rotación de cohortes (decisión 6 del 2026-10-27). |
| `estado` | `ACTIVO` \| `INACTIVO` | |
| `id_facultad_programa` | entero o `null` | Campo existente; se conserva. |
| `total_asignaturas` | entero | Solo lectura. Asignaturas en la malla del programa. |

Campos nuevos respecto al contrato actual: `jornada`, `semestres_nocturna`, `ingreso`, `estado`.

---

## 1. `GET /api/programas`: listar programas

Devuelve **todos** los programas, activos e inactivos (criterio 5), ordenados por nombre. Sin paginación (son pocos).

**200 OK**: arreglo de programas. Arreglo vacío si no hay ninguno.

## 2. `GET /api/programas/{code}`: ver un programa

**200 OK**: un programa. **404** si no existe: «Programa no encontrado».

## 3. `POST /api/programas`: crear programa

**Petición**
```json
{
  "code_program": "3846",
  "name_program": "Administración de Empresas",
  "jornada": "AMBAS",
  "numero_semestre": 10,
  "semestres_nocturna": 11,
  "ingreso": "SEMESTRAL",
  "estado": "ACTIVO",
  "id_facultad_programa": 4
}
```

**201 Created**: el programa creado, con `total_asignaturas: 0`. Un programa nuevo no tiene cohortes (criterio 3).

## 4. `PUT /api/programas/{code}`: editar programa

Mismo cuerpo que el `POST`. Se mantiene el comportamiento actual de **actualización parcial**: un campo ausente o `null`
conserva su valor. `code_program` no se puede cambiar: si viene y es distinto del de la ruta, responde 400.

Reglas al cambiar la jornada:
- A `DIURNA`: `semestres_nocturna` queda en `null`.
- A `NOCTURNA`: `numero_semestre` queda en `null`.
- A `AMBAS`: deben quedar las dos duraciones (las que ya tenía o las enviadas).

Editar no modifica mallas, cohortes ni coordinador (criterio 4). Se puede reactivar un programa enviando `"estado": "ACTIVO"`.

**200 OK**: el programa actualizado. **404** si no existe.

## 5. `DELETE /api/programas/{code}`: desactivar programa

**Cambio de comportamiento:** ya no borra. Pone `estado = INACTIVO` y conserva mallas, cohortes, coordinador y docentes
(RN-13). Si ya estaba inactivo, responde igual.

**204 No Content**. **404** si no existe.

## Validaciones (POST y PUT)

| Campo | Regla | Mensaje |
|---|---|---|
| `code_program` | Obligatorio en POST. Exactamente 4 dígitos. | «El código debe tener 4 dígitos» |
| `code_program` | Único. | «Ya existe un programa con este código» (409) |
| `code_program` | En PUT, distinto del de la ruta. | «El código del programa no se puede modificar» |
| `name_program` | Obligatorio en POST. No vacío. | «El nombre es obligatorio» |
| `name_program` | Máximo 100 caracteres. | «El nombre no puede superar 100 caracteres» |
| `jornada` | Obligatoria en POST. `DIURNA`, `NOCTURNA` o `AMBAS`. | «La jornada debe ser diurna, nocturna o ambas» |
| `numero_semestre` | Obligatoria si la jornada es `DIURNA` o `AMBAS`. Entre 1 y 20. | «La duración en jornada diurna es obligatoria y debe estar entre 1 y 20» |
| `semestres_nocturna` | Obligatoria si la jornada es `NOCTURNA` o `AMBAS`. Entre 1 y 20. | «La duración en jornada nocturna es obligatoria y debe estar entre 1 y 20» |
| `ingreso` | Obligatorio en POST. `SEMESTRAL` o `ANUAL`. | «El ingreso debe ser semestral o anual» |
| `estado` | Opcional en POST (por defecto `ACTIVO`). `ACTIVO` o `INACTIVO`. | «El estado debe ser activo o inactivo» |

El código y el nombre se guardan sin espacios al inicio ni al final.

**Guía para programas con las dos jornadas** (decisión 8 del 2026-10-27): al elegir `AMBAS`, el frontend sugiere
`semestres_nocturna = numero_semestre + 1`, editable. El backend no lo impone.

## Errores comunes
Formato del manejador global actual:
- Errores de validación de campos: `{"status": 400, "error": "Validation Error", "errors": {"codeProgram": "El código debe tener 4 dígitos"}}`. La clave es el nombre del atributo Java (`codeProgram`, `nameProgram`, `numeroSemestre`, `semestresNocturna`…), no el del campo JSON, como en el resto de la API (corregido el 2026-10-27).
- Resto de errores: `{"status": <código>, "error": "...", "message": "..."}`

| Código | Cuándo | Mensaje |
|---|---|---|
| 400 | Validación fallida | El de la tabla de validaciones |
| 401 | Sin JWT o JWT vencido | «Sesión no válida o expirada» |
| 403 | Rol sin permiso | «No tiene permisos para esta acción» |
| 404 | El programa no existe | «Programa no encontrado» |
| 409 | Código repetido | «Ya existe un programa con este código» |
| 500 | Fallo inesperado | El frontend muestra «No se pudo guardar el programa» |

## Mensajes que maneja solo el frontend
«Programa creado», «Programa actualizado», «Programa desactivado», «No se pudo guardar el programa», «No se pudo cargar»,
y las confirmaciones al guardar (criterio 2) y al desactivar.

## Fuera de este contrato
- Eliminar un programa sin cohortes (HU-041, sin sprint).
- Semestre de cada asignatura por jornada en la malla (HU-017 y HU-032).
- Bitácora de cambios (HU-058, sin sprint).
