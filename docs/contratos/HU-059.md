# Contrato API: HU-059 Cupos de estudiantes por curso/grupo

**Estado:** implementado en backend y frontend · **Fecha:** 2026-11-12
**HU relacionadas:** HU-014 (exportación futura), HU-045/HU-046 (programación y grupos), HU-047 (cursos excluidos), HU-058 (bitácora)
**Migración:** V34 (`V34__hu059_cupos_cursos_programacion.sql`)

## Alcance

1. Registrar y modificar el número de cupos de estudiantes de cada curso/grupo programado.
2. El administrador puede editar cualquier programa y siempre; el coordinador solo su programa y dentro del plazo.
3. No se permiten cupos en cursos `EXCLUIDO`.
4. El guardado es **por fila**: el lápiz habilita solo el campo de cupos de ese grupo y la solicitud envía únicamente las filas editadas.
5. Cada cambio queda en la bitácora (acción `EDITAR`, entidad `CURSO`).
6. El valor queda persistido en `cursos_programacion.cupos` para la exportación de HU-014.

## Roles

| Endpoint | Roles |
|---|---|
| `GET /api/programacion/cupos/config?periodoId={id}` | `ADMIN`, `COORDINADOR` |
| `PATCH /api/programacion/cupos` | `ADMIN`, `COORDINADOR` |

## GET /api/programacion/cupos/config

```json
{
  "maxPorGrupo": 60,
  "plazoAbierto": true,
  "puedeEditar": true,
  "admin": false
}
```

- `maxPorGrupo`: valor de `cda.cupos.max-por-grupo` (variable `CUPOS_MAX_POR_GRUPO`, por defecto 60).
- `plazoAbierto`: si la ventana `plazo_coordinador_inicio`/`plazo_coordinador_fin` está vigente.
- `puedeEditar`: `admin || plazoAbierto`. El administrador siempre puede editar.
- `admin`: indica si la sesión es de administrador.

## PATCH /api/programacion/cupos

Petición:

```json
{
  "periodoId": 7,
  "cursos": [
    { "cursoId": 812, "cupos": 30 },
    { "cursoId": 813, "cupos": 25 }
  ]
}
```

Respuesta `200`:

```json
{
  "cursos": [
    { "id": 812, "codigoCurso": "MAT101-50", "cupos": 30, "...": "resto de CursoResponse" },
    { "id": 813, "codigoCurso": "MAT101-51", "cupos": 25, "...": "resto de CursoResponse" }
  ],
  "mensaje": "Cupos de estudiantes registrados correctamente"
}
```

`GET /api/programacion` incluye ahora el campo `cupos` en cada `CursoResponse`.

## Validaciones y errores

| Caso | HTTP | Mensaje |
|---|---|---|
| Cupo nulo, cero, negativo o no entero | 400 | `Debe ingresar un número de cupos válido` |
| Cupo mayor al máximo | 400 | `El número de cupos no puede superar el máximo permitido (60)` |
| Curso excluido | 400 | `No se pueden asignar cupos a un curso excluido` |
| Curso de otro período | 400 | `El curso no pertenece al período indicado` |
| Petición sin período o sin cursos | 400 | `No se recibieron cupos para actualizar` |
| Coordinador fuera del plazo | 409 | `El plazo de edición ya cerró` |
| Coordinador edita otro programa | 403 | `Solo puede asignar docentes a cursos de su programa` |
| Curso o período inexistente | 404 | `Curso no encontrado` / `Período académico no encontrado con ID: {id}` |
| Error inesperado en el frontend | — | `No se pudo registrar la información de cupos. Intente de nuevo` |

## Reglas de negocio

1. **Alcance por rol.** El coordinador solo puede enviar cursos de su `code_program`; el administrador, cualquiera.
2. **Plazo.** El coordinador solo guarda si `ahora` está entre `plazo_coordinador_inicio` y `plazo_coordinador_fin`. El administrador no se bloquea por plazo.
3. **Guardado por fila.** La solicitud incluye solo los cursos cuya fila se habilitó con el lápiz o cuyo valor cambió; los demás conservan su cupo persistido.
4. **Cursos excluidos.** Se muestran con `—` y no admiten cupos.
5. **Bitácora.** Por cada curso cuyo valor cambia se registra `EDITAR`/`CURSO` con `valorAnterior.cupos` y `valorNuevo.cupos`, en la misma transacción.
6. **Persistencia.** Los cupos no se borran al regenerar la programación (la conciliación conserva el curso y su valor).

## Interfaz

- El coordinador reutiliza `ProgramacionCohortesView` con una sola pestaña: **«Cupos de estudiantes»**.
- El administrador conserva las pestañas de cohortes, generación y cursos, con la columna **Cupos** en «Cursos Programados».
- En la columna **Acciones**, junto a «Excluir», el botón con lápiz habilita únicamente el campo de cupos de esa fila; al terminar cambia a «Listo».
- «Listo» valida y guarda ese grupo en el mismo instante; no hay botón global de «Guardar cambios». Si el campo está vacío o el valor es inválido, «Listo» no cierra la edición y muestra el error.
- Éxito: `Cupos de estudiantes registrados correctamente`
